# Theia V4: shared cinema

## Product direction

Accepted by the maintainer on 30 September 2026 (decision 160). V3 ends with
3.4; there are no further 3.x releases planned. Desktop applications and the
server remain the active development and support priorities.

V4 develops shared viewing around a private media library:

- Watch parties with coordinated playback.
- A startup **Who's watching?** chooser for the library's local profiles.
- Comments on films, with likes and dislikes.

Direct messages and calls are outside the scope. These features do not introduce
a cloud account, telemetry or a mandatory hosted service. Profile selection must
remain separate from any future access-control decision; a local profile is not
automatically an authenticated user.

## Work to specify before implementation

1. Room ownership, invitations, playback authority, reconnect behaviour and
   synchronisation across different files or playback capabilities.
2. Profile selection, remembered selection and progression scoping at startup.
3. Storage, visibility, editing and removal of comments and reactions. Access
   controls need their own decision before exposing write routes remotely.
4. Accessibility, FR/EN wording and real multi-device acceptance checks.
5. **Linux engine (blocking).** The 3.4 Linux package ships Ubuntu's GPL libmpv,
   which cannot accompany a player under a non-GPL licence. No 4.x Linux package
   is published until an LGPL engine is adopted by its own pin entry
   (candidate: `player/theia-player/RENDER-LINUX.md`).
6. **Release gates for the licence change.** Licence audit of Go modules and Rust
   crates, the contributor agreement live, and README/spec wording consistent.

This is the accepted direction, not an implementation contract or a delivery
date. Implementation proposals must first record their data model, private-network
boundaries and acceptance criteria.

## Other clients

The existing web viewing interface stays available for phones and TVs, with
active viewing development and support ended. Web server administration and
settings remain maintained (decision 159). Dedicated mobile and TV clients are
deferred until the project has sufficient capacity; none is promised for V4.

## Optional supporter features after V4

Decision 161 records the maintainer's updated funding direction. V4's optional
shared-viewing/social features will initially be available free of charge.
When V5 work starts, some may become paid supporter features, without a monthly
subscription. The server, library and ordinary film/series viewing remain free;
From 4.0 the core is source-available under PolyForm Noncommercial, not open
source; 3.4.0 and earlier stay GPL-3.0 (decision 163).

The exact paid scope, price, purchase duration, entitlement mechanism and
distribution terms are not decided. Do not implement a payment gate. Any paid addition lives in a separate closed
module outside this repository (decision 163); how it meets the core needs its
own decision before any V4 code is written.
Those details need a separate specification and advance announcement.

The maintainer estimates V4 completion around late October/November 2026 and
the transition around late 2026/early 2027, potentially sooner if development
accelerates. These are estimates, not promised release dates.
