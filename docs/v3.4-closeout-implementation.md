## Measured changes

Windows amd64, Ryzen AI 9 HX 370. Synthetic SQLite library: 100 shows, 10
interrupted episodes each, 12 selected cards; three 500ms benchmark runs. The
maintainer was watching a film during this work; these are local measurements,
not an idle-device certification.

- Same **one-card-per-show** contract: batched median **2.96 ms/op, 30.0 KB/op,
  567 allocations**; N+1 median **7.62 ms/op, 103.4 KB/op, 2,527 allocations**.
  The batch performs two reads and omits files/next ids on home cards; playback
  loads the complete detail when needed.
- The original ungrouped row measured 2.43 ms/op. It returns a different selection
  and is not a valid speed baseline for the new grouped product rule. The first
  correlated grouped prototype regressed to 7.11 ms/op and was replaced. All
  intermediate results remain in `docs/archive/v3.4/series-*.txt`.
- The old main JS chunk was 571.47 kB / 179.88 kB gzip. The new main is
  **549.41 kB / 176.61 kB gzip**, with separate settings (30.17 kB), profiles
  (4.64 kB), film detail (1.60 kB) and help (0.98 kB) chunks. Extra
  features are included in the new build; chunk reduction is not proof of a
  faster native cold start. Vite's 500 kB warning remains.
- Large-grid fixture: 30 mounted cards from 1,000 at 969x609. This is DOM size,
  not a native frame-rate measurement. Focus, both ends and restored scroll are
  checked; the restoration initially failed because the exiting detail clamped
  scroll before the grid's spacers existed, and the regression now protects it.

## Native debug results, 30 September 2026

See `docs/archive/v3.4/native-runtime.json` for sanitised engine/page samples.
The debug player ran with the pinned, hash-matching engine, a backup of the real
SQLite library on 8395, and isolated native configuration/WebView folders.

- Real HEVC film and H.264 episode clocks advance with `gpu-next`, D3D11 hardware
  decoding and no reported decoder/display drops. The episode reads back audio
  track 2/subtitle track 1 and successor 12. Volume restores to 0.35; explicit
  `--mute` stays muted. These read-backs do not approve visual track menus.
- A real episode position of 213.458s survived a forced player stop and startup
  while its remembered server was offline. The saved address stayed selected;
  recovery cleared the outbox and the server read back exactly that position.
- A silent local HTTP server refused the native CLI health probe after 4.125s.
  This proves its timeout, not cancel-button latency in a WebView.
- Three generated 8-second episodes start at 1.8/20.4/39.1s. The final one stays
  ended for more than two minutes, with no fourth start or reported drop.
- At 200% DPI, the existing window probe reports 640x360 physical / 320x180
  logical, a visible bar and three visible controls. This forces a size below
  the interactive minimum track size. Fullscreen/resize interaction is untested.
- Computer Use navigated the real server's settings page and expanded its
  address section. Its Windows `listWindows`, `getApp` and `launch_app` APIs
  are absent even after refreshing; no native screenshot/click was possible.

The pass corrects explicit mute being overridden on restore, custom-install
maintenance choosing the standard directory, and literal percent/exclamation
characters in Windows deferred removal. It rejects installation/removal when
the program directory contains data/media. Installer tests now isolate scheduled
task identities and only clean their own registry subtree. Go tests/vet and
51 Rust tests, formatting and strict Clippy pass after these corrections.
The production Windows bundle was then installed from an appended self-contained
setup payload with seven components. Its registry/task names alone were linked
to test identities. The installed release player matches the build hash, repeats
the three-episode EOF chain and reports the OSD at 200% DPI. Three Start Menu
links target real installed files; the launcher starts its recorded server on
8396 and a second invocation keeps the same server PID. Registration repair
restores a deleted test App Paths entry. Running the installed uninstaller removes
the custom program directory, shortcuts, PATH and Apps/App Paths entries;
SHA-256 of the database/WAL and three fixture media files remain identical.
The real installed 3.3.6 Apps entry remains present. No TA proof processes are
left running. Details: `docs/archive/v3.4/windows-installation.json`.
Windows Settings/Flow Launcher UI, native fullscreen/quality interactions and
packaged Mac composition remain release gates. This candidate is **partially
verified**, not approved for publication.

## Verification commands

```powershell
# Go must also be on PATH so CLI subprocess tests actually compile their tool.
go test ./...
go vet ./...
cargo fmt --manifest-path player/Cargo.toml -- --check
cargo test --manifest-path player/Cargo.toml
cargo clippy --manifest-path player/Cargo.toml --all-targets -- -D warnings
npm run build --prefix player/ui
npm run check:previews --prefix player/ui
# Headless browser only, after starting the UI preview on localhost:5199.
npm run check:render --prefix player/ui -- http://127.0.0.1:5199/
node scripts/decisions.mjs
```

The installer CLI harness now links its subprocess with private registry roots
as well as temporary APPDATA/LOCALAPPDATA. Filesystem redirection alone did not
isolate Windows Apps or App Paths: `--uninstall` could delete the real keys even
with no installed files under its temporary directory. The in-process setup
suite already had TestMain isolation; the CLI subprocess was the missing boundary.
The installed 3.3.6 Apps entry and launcher App Paths were restored by the new
maintenance primitive, without replacing binaries or launching the player. The
full CLI/setup suites then run with private roots; TestMain checks that the real
registration presence stays as it was.

OS/DPI, film/episode codes, chosen tracks, positions and actual result. Do not put
private paths or addresses into a copied public diagnostic. Keep the existing
running installation untouched until the maintainer authorises the visible test.
