# Theia 3.3.2: the product has a name

If you use Windows x64, download this one file:

**[Download Theia 3.3.2 for Windows x64](https://github.com/Benitoow/theia-media/releases/download/v3.3.2/theia-setup-windows-amd64.exe)**

It installs the server, the native player, the `theia` command and the pinned
video engine, verifies every downloaded byte against GitHub's SHA-256 digest,
puts the installation on your `PATH` and registers it with Windows. If this
machine must install without a network connection, use the
**[complete offline bundle](https://github.com/Benitoow/theia-media/releases/download/v3.3.2/theia-3.3.2-windows-amd64.zip)**
instead, unpack it and run `theia-setup.exe`.

Everything else under *Assets* is a component consumed by the installer or the
automatic updater.

## What changed

- **`theia` is a command.** The installer puts the installation on your `PATH`,
  so a terminal has it: `theia` starts the server if nothing answers on its port,
  waits for it and then opens the player; `theia server` and `theia player` start
  one half alone; `theia -version` prints the build. `theia-server` and
  `theia-player` keep their own names for anybody who wants the console - the
  server prints its log there.
- **Windows knows the word too.** `theia.exe` is registered under App Paths, so
  the Run dialog and the launchers that read it resolve `theia`, and the Start
  Menu entry **Theia** now starts the launcher instead of the player. That entry
  used to open a player that could not find a server and cannot start one.
- **An empty library no longer breaks the player's home screen.** The 3.3.1
  server described a home screen with no rows as `"rows": null`, and the window
  answered "the home screen could not be loaded" about a library that was simply
  empty - which is what a fresh installation has. The server sends `[]` now, and
  the player tolerates the old shape, so a 3.3.2 player also works against a
  server that is still 3.3.1.
- **`theia-setup --uninstall` takes it all back out**: the shortcuts, the
  applications-list entry, the `PATH` entry and the App Paths entry - and keeps
  `%APPDATA%\Theia`, with your library and watch history in it.
- **The offline bundle carries `theia.exe`**, and `theia-setup --check` lists it
  because that list now comes from the same one the installation uses.

## Verification boundary

Locally on Windows, the web build passed with zero Svelte warnings, all 43 unit
tests passed, the three-viewport browser guard passed 81 tests with its three
documented skips, and the generated-media playback guard passed 47 tests with its
five documented skips. Go tests and `go vet` passed, the native player's 11 Rust
tests and the real-browser render check passed, and all six server targets plus
the Windows x64 setup cross-compiled. A staged folder built from this tree was
then installed for real: the four command names resolve from the user's `PATH`,
App Paths holds `theia.exe`, the applications list carries the version asked of
the installed server, the four entries point at the launcher and the two
programs, `theia` with nothing running started the server and opened the player,
and the registered uninstall removed both registry entries while keeping the data
directory before the reinstall put everything back. The compatibility fix was
measured against the published 3.3.1 binary: this tree's player, pointed at it,
draws the empty-library screen where it used to draw a failure.

Not driven here: **Flow Launcher's own window and the Windows search box** - both
read exactly the Start Menu folder and the applications-list entry that were read
back with Windows, which is what decision 123 established about those launchers.
