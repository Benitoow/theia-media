# Theia 4.4.3 — the interface follows the update

4.4.3 repairs one path: a household that updated to 4.4.2 from a tester build saw
the server change version while the interface stayed on the tester build, and the
player's check kept saying it was current. The update button now reads a tester
build as older than its release, and the final interface reaches the player as a
pack again.

The server, library, ordinary viewing and all features in this release remain
free for noncommercial use. There is no cloud account or telemetry.

## Updating from 4.4.2 or a 4.4.2 tester build

This is a **product release**: the native player does not change. Update from
Theia's own update button - *Settings → Updates*, then **Check for updates**. The
server is replaced, and the signed interface pack that carries this repair is
checked, kept, and applied the next time the player starts. You do not need to
run a setup again.

A tester installation whose interface is still marked `4.4.2-test.3` takes this
pack as well: 4.4.3 is newer than it. The technical details then show the
interface on 4.4.3; the native player line keeps whatever shell that installation
has, which is what the line is for.

## Updating from 4.4.1 or older

The 4.4.2 interface needs the player introduced by 4.4.2, and a pack cannot
replace a shell. Run the **4.4.3 setup** once: it carries the stored 4.4.2 player
and this release's interface. Your library, profiles, watchlists, preferences and
viewing history stay in place. Windows ARM64 and Linux ARM64 keep the 4.2.1
setups the website links, as in 4.4.2.

## What changes

- **A tester build is older than its release.** The interface compared versions
  by their three numbers alone, so `4.4.2-test.3` counted as `4.4.2`. It now
  follows the same order as the setup and the shell: a prerelease ranks below its
  release, and build metadata is ignored. The update button no longer mistakes a
  finished update for a current one, and no longer skips the setup a shell
  release needs.
- **The interface travels as a pack again.** 4.4.2 was a shell release and
  published no pack, so an installation that had confirmed a tester pack had
  nothing newer to fetch. 4.4.3 publishes the signed pack, and a level-3 shell
  installs it silently.

Nothing else changes: no library scan, playback, native contract, Firebase rule
or settings behaviour is touched.

## Downloads

4.4.3 publishes the six standalone servers, the setups for **Windows x64, Linux
x64, macOS Apple Silicon and macOS Intel** around the verified 4.4.2 player, and
the signed interface pack with its signature. Windows ARM64 and Linux ARM64 keep
the 4.2.1 setups the website links, until their native checks can run.
