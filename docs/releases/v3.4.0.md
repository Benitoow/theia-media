# Theia 3.4.0

Unpublished preparation draft. This release consolidates the native V3 player and its installation path before
work moves to V4. The complete downloads remain Windows x64 and macOS Apple
Silicon. The six server binaries keep their exact names for installed updaters;
Windows ARM64, macOS Intel and Linux are not presented as complete downloads.

## What changed

- Each complete platform has one self-contained setup. It carries the server,
  player, launcher, engine and licence texts, and can install without downloading
  the same components again.
- The macOS player now has a render surface in the actual Tauri application.
  Publication still requires generated-film frames and visible OSD on the
  packaged Apple Silicon product.
- `theia` finds the installed player through the Mac's symbolic link and uses
  the installation's recorded data directory and port when starting its server.
  The setup and server read the same record.
- The native player's connection screen distinguishes an unreadable address
  from a server that did not answer, and trims spaces from a copied address.
- A manually selected server address survives player restarts. Settings can
  disconnect and change servers; an offline saved address stays selected until
  the viewer chooses another. Connection attempts no longer block the UI.
- Film cards open a native detail with the server's TMDB synopsis, credits and facts
  before playback. Saved playback languages are applied before a film or episode
  loads, and the subtitle menu accepts its off choice.
- The blurred card fill is darker. Fullscreen removes the window's rounded
  corners, and the window restore button exits fullscreen cleanly.
- The latest interrupted episode can own the home hero. Series details show
  its saved position and open its season; returning from playback refreshes
  progress. Resume remains scoped to the active profile.
- Leaving a preview while it is building no longer prevents the next hover
  from requesting it. Native search matches titles without their accents.
- Windows registration can be restored with `theia-setup --repair-registration`
  when an existing install is missing from Settings → Apps.
- Window-sized player artwork requests the original cached image instead of
  enlarging the card-sized copy.
- The browser remains the server settings and administration surface. Browser
  playback support has ended; watching is the native player's responsibility.

- Cancelling a connection rejects late answers. A saved offline server is retried
  quietly with backoff; partial film/series failures preserve the usable half.
- Unsent playback progress survives locally, keyed by server/profile/media, and
  is retried without erasing a newer position. The player reports pending saves.
- Episode cards offer watched/reset actions and a completed badge. A series
  suggests its next unwatched ordinary episode; the continue row keeps one card
  per show. A next-episode button appears near EOF, with a 10-second grace period
  for optional autoplay.
- Volume/mute and safely clamped window geometry persist on the device.
- Keyboard help, a search shortcut and a copied diagnostic without private
  addresses/paths are available. Quality explains why alternatives are unavailable.
- Settings/details load on demand; large grids render a bounded set of complete
  rows, preserving keyboard access and detail-return scroll. Preview networking
  and blob memory are bounded. The continue row batches its card metadata reads.
- Windows player maintenance restores Windows Apps and launcher registration.
  Installer CLI regressions now isolate registry keys as well as temporary files.
- Custom installs use their own program directory for maintenance and removal.
  Setup refuses a program directory containing data/media; Windows cleanup
  preserves literal `%` and `!` in a directory name. Test scheduled tasks are
  isolated from the installed product. Native `--mute` survives audio restoration.

## Limits

The macOS application is distributed ad-hoc signed, without notarisation.
Hardware video decoding, an interactive audio endpoint and Gatekeeper's first
launch still need checks on a personal Mac. Linux has no pinned player engine
or complete release target. The proof runners do not substitute for those
checks.
Native fullscreen and series quality changes still need a visible playback
check on the maintainer's machine. The packaged Apple Silicon film-and-OSD proof
remains a release gate; this draft is not a published release.
Series metadata now carries its original language for episode VO selection;
existing matched metadata is refreshed once through the normal enrichment queue. The new series
resume detail contract requires both the 3.4 server and player; an older server
provides only the player's partial fallback from already fetched episodes.
