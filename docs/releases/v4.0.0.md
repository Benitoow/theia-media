# Theia 4.0 — a fresh start for the core

3.4 closed V3 and said the app had reached its core. 4.0 is what I wanted to
build on top of that: a clean **Theia Core** (the server, the library and the
native player) that works without being babysat, plus the first pieces of a
shared cinema. Who is watching tonight. What your friends are watching right now.

**4.0 is free, entirely.** The server, the library, ordinary viewing, and every
new feature in this release cost nothing.

## Where this release stands

Theia has reached its core level. That means the foundations are now clean:
the installer, the player, the server, the way films are recognised, the Linux
package, the licence. From here, the app will keep changing, and those changes
will reach everyone for free, for a duration I cannot give you yet.

I do not know when the features I add from 4.0 onwards will become paid, or
which ones. That is a decision I would rather take openly, with the people who
use Theia, than alone. Nothing is paid today, no payment code exists, and
nothing will move behind a paywall without being announced well before it
happens. Your library, the server and watching your films are not part of that
conversation: they stay free.

**Upgrading from 3.x:** run the new setup. It reads the installation it finds,
offers to update it in place, closes the running programs, replaces them and
starts the server again. Your library, progress and configuration stay where
they were. An automatic server update alone does not replace the old player.

On macOS and Linux, make the setup executable (`chmod +x` and its filename),
then run it. Mac apps are ad-hoc signed and not notarised, so macOS may ask you
to allow the app in Privacy & Security on first launch. Windows binaries are
unsigned and may show a reputation warning.

Ubuntu needs two desktop packages. The media engine no longer is one of them:

```sh
sudo apt install libwebkit2gtk-4.1-0 libayatana-appindicator3-1
```

## What is new

### A shared cinema, first steps

- **Who's watching?** When a server has two or more profiles, the player asks
  at startup. The last answer is already focused, so Enter alone is enough.
  You can create a profile from that screen, and a setting turns the question
  off for households that always watch as the same person.
- **Friends.** Every profile has a code. Enter a friend's code and they receive
  a request they can accept or decline; once both sides agree, you see what the
  other is watching *right now*: poster, title, and for a series the season and
  episode. Nothing else is shared: no history, no progress, no library. It is
  kept in memory for ninety seconds and never written down.
- **Friends on other servers.** A friend can be in another household, on their
  own server. It travels through Theia's built-in WireGuard tunnel: no relay, no
  account, no Theia-operated service. Sending a request does not need you to
  open a port. If a router refuses to open one by itself, the friends sheet lets
  you type its public address by hand.
- **Discord Rich Presence.** Off by default. When switched on, it talks only to
  your own Discord client on your own computer. Showing the title of what you
  watch is a second, separate switch. While you browse the menus it says
  "In the menus" and never a title.

### The installer, rebuilt

- One full-screen program with the Theia icon, the steps on a rail, and no more
  scrolling form.
- It reads the machine before asking: your language from Windows (and keeps it),
  film folders suggested from your drives, an existing installation recognised
  and updated rather than overwritten.
- A port held by another program is moved for you. Running Theia programs are
  closed and the server is started again afterwards.
- Refusals are explained in your language. A last page waits for the server and
  opens Theia.

### Better recognition of your files

- Results are chosen by exact title and nearest year, so a film beats its remake.
- Accents, articles and ampersands no longer cause misses; sequel numbers in
  digits or Roman numerals, and titles written before a subtitle, are tried.
- File names carrying French and streaming tags, `H.264` written with a dot,
  a website in front, or an edition written in words are read properly.
- A bare `movie.mkv` takes the name of the folder around it, `Alien (1979)/`.
- More episode spellings: `S01 E02`, `Saison 1 Episode 2`, and inside a season
  folder `Episode 05`, `E07 - Title` or just `05 - Title`.

### Linux, now with a clean engine

- The Linux player ships its own LGPL media engine, beside the player, with the
  licence text of every library it carries. Ubuntu's `libmpv2` is no longer
  needed.
- Both CPUs (x64 and ARM64) install the package on a real Ubuntu 24.04 runner,
  play a generated film and paint the player's controls before anything is
  published.

### The player's window and settings

- Settings are grouped: Preferences (General, Playback, Subtitles, Discord) and
  Information (Statistics, Server and updates).
- The frameless window now resizes by its corners as well as its edges.
- A maximized window no longer leaves a one-pixel line showing the desktop at
  the bottom when the taskbar is hidden.
- If the server you chose does not answer, the player falls back to the one
  running on the same machine, starting it first if needed.
- The icon is now a T over the sun, in the web interface, the installer and the site.

## The detailed list

- Startup *Who's watching?* chooser, with a setting to skip it (decision 165).
- Friends sheet with codes, requests, accept and decline, and a manual router
  address (168, 169, 171).
- Friends shown as cinema cards with their poster, a blurred backdrop and their
  profile picture (168).
- Opt-in Discord Rich Presence over local IPC; the title needs a second consent
  (166).
- Grouped settings, "In the menus" status, diagonal corner resizing (172).
- Fallback to the machine's own server when the chosen one does not answer (171).
- A longer, patient wait on friends and remote-access calls, so the server's own
  refusal is read rather than a generic one (169).
- The maximized-window pixel returned to the window (147).

**Server and network**
- Friend codes naming a server's key, tunnel port and public endpoint (168).
- Friend requests delivered to a mailbox, proven through the sender before being
  shown, and answered with the name they reached or "this person does not exist"
  (169).
- A friends-only tunnel while remote access is off: no device can join it (169).
- WireGuard peers updated one at a time, so a new friend no longer tears down the
  sessions of the others (169).
- A Windows tunnel no longer goes deaf after one ICMP "port unreachable" (168).
- The tunnel is brought up before it is configured and its port read back, which
  fixes a race that could report a tunnel running on a port nobody had asked for
  (175).
- An abandoned friend request leaves nothing behind (169).
- The settings page states the router's real reason when remote access fails.

**Library**
- Better title, year, edition and episode recognition (173).
- The films/series ratio in Statistics is drawn in two colours.
- A hand-built installer always carries the TMDB key (173).

**Installer**
- Full-screen rebuild, language kept, folders suggested, existing installation
  updated in place, running programs closed, errors said in your language (170).

**Linux**
- LGPL engine pinned by digest for both CPUs, in `TheiaPlayer/` (174).
- Audio goes through PulseAudio or ALSA first, which every PipeWire desktop
  serves, after a measured crash in the engine's own PipeWire output (174).
- Native installation, film and controls proven on Ubuntu 24.04 x64 and ARM64.

**Project and licence**
- From 4.0 the source is source-available under PolyForm Noncommercial 1.0.0.
  3.4.0 and every earlier release stay under GPL-3.0 for good (163).
- Licence audit of every Go module and Rust crate is now a gate that must pass
  before anything is published (163).
- Contributor agreement in place (163).
- A one-page public site (164).

**Security and upkeep**
- `source-map-js` updated past a published denial-of-service advisory.
- The whole six-platform release pipeline was run end to end without publishing
  anything: tests, interface checks with a real browser, licence audit,
  endurance run, native installation and film on every platform, and an exact
  check of the public downloads.

## What I could and could not verify

- All six desktop packages build, install and play a generated film with
  painted controls on a real runner.
- Friends were verified with two real servers on one machine and in the native
  player. Two field tests between two households found real faults, now fixed.
  **A clean run between two households over the internet is what I still need
  from you.** If you try it, tell me what happened, including when it works.
- Hosted runners cannot establish hardware decoding performance, real audio
  endpoints, HDR output or a first Gatekeeper launch on your own computer.
  Physical Mac hardware decoding and HDR remain unverified.
- Linux uses software decoding and SDR. Hardware acceleration and HDR output are
  not available there yet. Other distributions than Ubuntu 24.04 are unverified.
- Phones and TVs keep using the existing web viewer. No dedicated app has a date.
