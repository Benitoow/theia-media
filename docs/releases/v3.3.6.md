# Theia 3.3.6

Windows x64 and macOS Apple Silicon remain the two complete platforms. Six
server targets and fourteen release assets are provided. The other four targets
have a server binary only, because no native player has been verified for them.

## What changed

- The Windows offline archive now passes its version to the native player build
  and rejects a reused player bundle whose version differs. Its server, setup,
  player and launcher report the same version as the separately built components.
- Rust, Tauri and the two frontend packages now name 3.3.6. A duplicated Rust
  test attribute was removed, and the profile URL contract is executed by the
  test suite. Clippy fixes keep the serialized subtitle setting unchanged.
- The release workflow runs Rust tests and Clippy for both native players and
  audits the player UI dependencies. Its Windows job extracts the offline ZIP,
  installs it on a disposable runner and checks the Windows Apps, App Paths,
  PATH and Start Menu entries. The macOS proof workflow preserves its logs,
  then fails when a recorded check failed. Its verifier finds the offline
  archive by the player's reported version instead of a fixed 3.3.4 path.
- The release surface gate compares each platform's standalone server, setup,
  launcher and player bundle byte for byte with the copies in its offline ZIP.
  A mismatch fails the non-publishing dispatch and blocks publication.
- The Go ZIP extractor now recreates macOS framework symlinks after ordinary
  files and refuses links that escape the destination. Previously, installing
  from a ZIP would turn the 11 links in the published Apple Silicon player bundle
  into text files. The macOS release job now installs from the offline ZIP and
  checks the installed links and player executable.
- Folder-based macOS installation now keeps the app bundle's file permissions.
  The published 3.3.5 bundle has four regular files with mode `0644`; the old
  copy path made every regular file `0755`. The release job now installs both
  from the ZIP and from its extracted folder, then checks links, permissions
  and `codesign --verify --strict` on both installed apps.
- The macOS player updater now recognises the existing `Theia.app` directory,
  swaps the whole tree and removes its previous copy after a successful update.
  Its tests use an app-bundle tree on macOS rather than a flat executable.
- The OSD render guard ignores its periodic statistics query when checking the
  commands triggered by the Mute button.

## Verified locally

- All six Go server targets cross-compiled with CGO disabled. Go tests and vet,
  30 distinct Rust tests, Clippy with warnings denied, frontend checks and
  builds, both npm audits, the decision index and contrast guard passed.
  `govulncheck` found no reachable Go vulnerability.
- The macOS Apple Silicon setup and launcher also cross-compiled with CGO
  disabled; neither was run on a Mac for this revision.
- The Windows offline archive built before the macOS ZIP extraction fix contains
  eight expected files and all four programs report `v3.3.6`. The bundled
  libmpv DLL matches its pinned SHA-256.
  A mismatched player version is refused before the archive is rebuilt. The
  archive was rebuilt from the current commit in CI.
- With the server extracted from that archive, 81 browser layout cases passed
  (3 skipped), and 51 generated-media playback cases passed (5 skipped). The
  OSD render guard passed at desktop and phone sizes.
- The archived Windows player played a muted 20-second H.264/AAC fixture with
  the pinned engine: position advanced from 0.25 to 13.25 seconds, the OSD
  rendered frames, and the diagnostics reported no dropped frames in that run.
- The parity guard passed seven component comparisons on the local 3.3.6
  Windows assets; changing one byte in the standalone server made it fail.
  Its macOS path passed 60 comparisons on the five public 3.3.5 Apple Silicon
  assets, whose downloads matched their published SHA-256 digests. This checks
  the guard against real macOS packaging; CI then checked the 3.3.6 bundle.
- The complete Go test suite and `go vet ./...` passed after the ZIP extraction
  fix, and the macOS Apple Silicon setup cross-compiled without CGO. The
  escaping-link regression passed on Windows; the link-creation test
  was skipped because this Windows account lacks symlink privileges. Compiled
  for Linux and run under Ubuntu WSL, the extraction tests passed, including
  link creation and replacement. The same extractor recreated all 11 live
  framework links from both public 3.3.5 macOS ZIPs. The macOS release job
  was subsequently checked by CI on the platform that ships it.
- During local preparation, all six server targets and the Windows x64 and Apple
  Silicon setup and launcher programs cross-compiled with CGO disabled. Build
  metadata confirms the target, `CGO_ENABLED=0` and `-trimpath` for all ten;
  the local commands also used `-s -w`. Windows server, setup and launcher
  reported `v3.3.6`, as did the Linux x64 server run under WSL. These checks
  establish build configuration and startup, not a measured speed gain.
- The app-bundle copy regression passed under Ubuntu WSL: executable and
  non-executable modes and the framework symlink survived. The full Go suite,
  `go vet ./...` and an Apple Silicon setup cross-build passed after this fix.

## Release verification

The non-publishing [release run](https://github.com/Benitoow/theia-media/actions/runs/36317731499)
passed every gate on the prepared code: six server builds, both native players,
the Windows installer registration check, macOS installation from both the ZIP
and extracted folder, rollback and endurance checks, and the interface guard.
The release surface contained exactly fourteen assets; 67 component comparisons
between the standalone assets and offline archives matched byte for byte. The
separate [macOS proof run](https://github.com/Benitoow/theia-media/actions/runs/36317731187)
passed 21 checks with none failed and two requiring a person to inspect them.

The Windows native playback check above used a generated fixture. The household
library, the downloaded 3.3.6 installer in Windows Apps and Flow Launcher, and
interactive macOS audio, Gatekeeper, hardware decoding and perceived OSD
composition were not rerun for this release. The Windows installer registration
gate ran on a fresh disposable runner, not on the maintainer's machine.

On the maintainer's currently installed **3.3.5**, the three Start Menu links
and the PATH entry are present, but the Windows Apps uninstall key and the
`theia.exe` App Paths entry are missing; `theia-setup --check` reports
`Application: no`. This does not establish how the entries went missing. The
fresh 3.3.6 runner installation passed its registration checks; the maintainer's
installed system and Flow Launcher still need a separate read-back.
