# Theia 5.3.1 — the anti-spoil mode follows the profile, and a paired copy keeps its opening and credits

**The anti-spoil choice now belongs to the profile and follows it from one series to the next, a reopen and a relaunch instead of being forgotten each time. An episode played from a paired server now offers *Skip opening*, its post-credits scene and the ending countdown, read from the origin that holds the file, and that countdown starts at 30 seconds rather than 31.**

Theia 5.3.1 is a **Product Release** (decision 196) repairing two behaviours reported on 5.3.0. The native player shells (Rust, libmpv) are the 5.3.0 ones pinned in `player/shells.json`; nothing native changed. What reaches the desktop travels in the signed interface pack `theia-ui-5.3.1.zip`; the six servers and the approved setups are rebuilt around the pinned shells. The Android application is a new APK (`theia-android-5.3.1.apk`, version code `50301`), because the phone's page is packaged in it.

---

## What arrives with 5.3.1

### 1. The anti-spoil mode is remembered by the profile (decision 202, amended)

The *Mode anti-spoil* switch used to live only in the series page that was open: leaving it, opening another series or relaunching the player started with protection off again, so the mode protected only the record somebody had just armed.

The choice is now stored with the profile's local preferences, beside its audio and subtitle choices: it follows you from one series to another, survives a reopening and a relaunch, and each profile keeps its own. Turning it off remains the deliberate reveal; nothing is sent to the server, to a room or to friends.

### 2. A paired copy keeps its opening, post-credits scene and ending (decision 225, amended)

A series held by a paired server plays through this installation's proxy, and the episode therefore has no local file to read chapters from. The player used to skip the segment lookup entirely for such a copy, so *Skip opening*, *Go to the post-credits scene* and the ending countdown were absent even when the origin's file named its chapters.

The server now answers `GET /api/ecosystem/v1/copies/{ref}/segments` by reading the origin's own segment route with the same grant and private-address rule as the stream. It passes only the closed marker vocabulary with bounded timestamps, answers the same three states as a local file (ready, building, unknown), and never guesses a marker from a runtime percentage. The player asks that route while a composed copy plays, so the three surfaces behave as they do on a local file. A cloud folder, a sleeping origin or an owner that names no chapter still answers unknown: nothing is invented.

### 3. The countdown starts at 30 seconds

The ending's deadline and the instant it was displayed came from two separate readings of the clock, so the visible countdown opened at 31 seconds. Both now come from one reading: it opens at 30, as decision 199 requires.

## Updating

- **The desktop player and server (Windows, macOS, Linux):** the interface pack updates from *Settings › Updates* and the player restarts on its own; the server updates the usual way, from the player or from the setup. No new shell.
- **Standalone server:** `theia-server-*` binaries are rebuilt for all six targets.
- **Android:** install `theia-android-5.3.1.apk` (version code `50301`), signed with the same key as 5.0 and later, so it updates them in place.

## What was and was not checked

- **Verified locally:** `go test ./...` (including the new copy-segments tests), `go vet ./internal/api`, the player's `npm run build` (`check:i18n`, `tsc --noEmit`, `check:contract`, `check:client`), `check:episode` (opening, post-credits, the three composed cases), `check:unified` (the composed page and its parity matrix), the full `check:render` bench on the rebuilt bundle (French and English, 320 to 1920 px, including the spoiler suite), `node scripts/decisions.mjs`, and `build.ps1` plus `build-player.ps1`.
- **Verified on a real local file:** a chaptered MKV generated for the test, read through the server's segments route: the opening, ending and post-credits markers came back with their timestamps.
- **Not verified:** a physical native playback session of the new paired-copy path, a real two-household pair naming its chapters, anything on a physical phone or television, and the Android build itself (it is signed locally by the maintainer). The copy-segments proxy is exercised against a paired test server and a stand-in segment endpoint, not against the maintainer's own paired household.
