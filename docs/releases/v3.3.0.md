# Theia 3.3: the native generation

Theia 3.2 ended on a question I did not answer: does Theia have to stay in your
browser?

I thought about that release for a long time, and it taught me something I had
been avoiding. Every difficult week I spent making playback behave inside a
browser was a week spent pushing against a ceiling that is not mine to move. The
browser is a wonderful thing and it is not built to hand a film to an amplifier.
That is the limit, and no amount of work on my side removes it.

So I rebuilt Theia as programs instead. Not in a weekend: this has been a week
and a half of work, closer to two, and it did not start from nothing - I already
had a working prototype of the desktop application running before 3.2 shipped.
This release is that prototype finished, measured and put in your hands.

Films now play in **Theia itself**.

## The three programs, in plain words

Theia used to be one file that did everything. It is now three, because a
program that reads your folders and a program that draws a film on your screen
have nothing in common once you look closely.

| | |
|---|---|
| **`theia-server`** | The part you already know. It indexes your folders, keeps the library, and serves the files and the web interface. Still one small program with nothing to install alongside it. |
| **`theia-player`** | The new one. A window, the film drawn directly by a real video engine, and the same Theia interface floating on top of it. This is where films are meant to be watched now. |
| **`theia-setup`** | The installer, and the only file you download. It asks what this machine is for and sets up the two others accordingly. |

If that sounds like more moving parts, it is - and it buys three things a browser
cannot give you:

- **Your sound reaches your amplifier.** A browser can only decode audio and send
  it as PCM. Theia now passes the original stream through untouched - Dolby
  TrueHD and Atmos, DTS-HD Master Audio, and the rest - for the amplifier to
  decode. If your machine refuses the raw stream, Theia notices the film has not
  started, goes back to decoded sound, and resumes **from where it was**, then
  tells you why in a sentence rather than an error code.
- **Your picture is the picture.** The file is read as it is - Matroska included,
  which browsers do not read natively - with hardware decoding and the Dolby
  Vision profile 7 enhancement layer carried properly, not silently reduced to
  its HDR10 base.
- **Your subtitles work.** A subtitle file sitting next to the film is found and
  used, which a browser cannot do over HTTP. Embedded subtitles, even the
  image-based ones, are read from the file itself.

**The web interface has not gone anywhere.** It is still the complete
administration surface, and it still plays anything a browser can decode. It is
simply not where the best picture and sound live any more. Your progress is
shared: start a film in the browser, finish it in the player, or the other way
round.

## The numbers, without theatre

These numbers were taken on the development machine (Windows 11, Ryzen AI 9 HX
370, Radeon 890M). They describe this machine, not every machine, and the ones
that did not improve are here too.

| What | Result |
|---|---:|
| Reading a 250-film library | **0.7 s**, 107 KB, two requests |
| Scanning 11 real files (118.2 GB) | **1.03 s**, 0 problems |
| Playing a 53.79 GB UHD remux | hardware decoding (`d3d11va`), `gpu-next` on a 10-bit surface, the TrueHD track chosen, position stored and resumed at exactly the stored second |
| A 1080p HEVC MKV a browser cannot play, six seconds to the end | **0 dropped frames**, `A-V: 0.000` throughout, 48 frames in two seconds at 24 fps |
| First frame, cold | ~240 ms of shader compilation, once, then never again |
| What you download | **58.1 MB** zipped, 135.6 MB unpacked |
| Of which the video engine | 95.4 MB - it is most of the archive, and it is replaceable |

The library the server used to hand over in fixed pages of 60, then 200, now
arrives whole: two requests, and the same three-card row the player has always
drawn. Nothing about the server got slower to pay for the new player - the
player is a separate program that asks it for files.

## Setup, and what it will not do

One file is the download. `theia-setup` asks **six questions** - which language
Theia should speak, what this machine is for, where its data lives, which port it
listens on, what name it answers to, and which folders hold your films - and it
shows you the whole plan before writing anything.

- **The language is asked because the product has two.** English is the base and
  French ships complete. Your answer sets what the interfaces open in *and* what
  the film information is fetched in, so a French household gets French titles
  and an English one gets English ones.
- **The role is declared, never guessed.** A mini-PC in a cupboard and a
  home-theatre PC have the same hardware fingerprint, so Theia asks: all-in-one,
  server only, or player only.
- **It never asks for administrator rights.** On Windows that means a per-user
  startup entry when the installer is not elevated, and a scheduled task when it
  is - and the tool tells you which one it used instead of swapping them quietly.
- **Everything it downloads is checked** against the SHA-256 digest GitHub
  publishes for it. A file that does not match is deleted, not kept.
- **Nothing needs the network** if you would rather not: the release also
  publishes an archive holding every file. Unpack it, run the installer from
  inside the folder, and it installs from what is beside it.

The command line does everything the form does, for a scripted or repeatable
install: `--role`, `--lang`, `--data-dir`, `--install-dir`, `--library`,
`--port`, `--service`, `--from`, `--json`. `theia-setup --check` reports what the
machine is configured as; `theia-setup --update` updates the server through the
same digest-verified path the server uses on itself.

Nothing is code-signed. Windows may show a reputation warning on first launch,
and macOS may require **Privacy & Security → Open Anyway**. That is what a
project at this scale looks like, and it is not a sign that something is wrong
with the download.

## Upgrading from 3.2

**Your installation updates itself, normally.** This release publishes the server
under its new name *and* keeps a byte-identical copy under the old one, for this
release only. An installed v3.2 asks for the old name through the updater it
already carries, finds this release, installs it, and lands on a version that
knows the new names. Those transitional copies disappear in the next release,
which is exactly what they are for.

The player is a separate, replaceable program on purpose: point `THEIA_LIBMPV`
at your own build of it and the player uses that one instead of the one beside
it.

## What is verified, and what is not

This is the part release notes usually leave out. This project does not.

**Verified on Windows 11**: hardware decoding and rendering into the player's own
window with zero dropped frames; the interface drawn over moving video; the audio
fallback above, with the film resuming where it stopped; track selection; a real
v3.2.0 installation updating into this release through the transitional names -
including the negative control, where removing those names makes the same
installation refuse to update, correctly, rather than install something wrong.

**Not verified anywhere**: a TrueHD or DTS-HD stream actually reaching an
amplifier - the development machine has no receiver and one audio endpoint, so
the mechanism is proven and the result is not; the composite pixels of the
interface over moving video at speed, which needs eyes on it rather than a
screenshot; and **macOS and Linux, which are written and have never been run**.
The player is built for Windows only in this release, for that reason. Television
and mobile applications remain out of scope here - they are the next generation,
not a promise.

## The engine, and its licence

The player ships libmpv, built for libmpv by
[`zhongfly/mpv-winbuild`](https://github.com/zhongfly/mpv-winbuild), LGPL-2.1-or-later.
The archive and the library are both pinned by SHA-256 in `player/libmpv.json`,
the build refuses anything whose digest does not match, and
`theia-player --diagnostics` prints the source, both digests and the version the
loaded library reports. The LGPL text travels in the bundle, and the library
stays a separate file you may replace.

## What comes next

**3.3.1 and 3.3.2 are the bug releases, and they land within the week.** The
large faults are already fixed - everything I found putting this on a real
library of 274 films and watching it for hours - so what is left is small:
details of the interface, wording, rough edges of the experience, and whatever
you tell me about. A 3.3.3 may follow if the list deserves one. If something does
not behave, the [Discord](https://discord.gg/p4Rp4zHdHf) is the fastest way to
reach me.

**Then 3.4, within two weeks: the television, and the mobile.** It is written
down in the spec and in the decision record - desktop applications entered the
scope with this release, and the two remaining screens come next. It is a much
bigger job than it sounds, because it is two more toolchains and two more ways of
shipping, done by one person.
