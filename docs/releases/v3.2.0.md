# Theia 3.2: the engine takes over

This release started with a very ordinary problem: one large UHD remux could
bring the player to its knees even though everything looked correct on paper. I
could have added two patches and moved on. Instead, I rebuilt the playback path,
measured every important choice, and dealt with the less glamorous parts too:
process cleanup, updates, large libraries, hardware selection and diagnostics.

Theia 3.2 is not a screen full of new buttons. It makes the **Play** button much
more worthy of your trust.

## The numbers, without theatre

These measurements were taken on the development machine under Windows 11. The
library figures use a synthetic database containing 10,000 films. The media
figures compare FFmpeg 6.1.1 and 8.1.2 over three alternating runs with the
player's production arguments. They describe this machine, not every machine.

| Scenario | Before | After | Change |
|---|---:|---:|---:|
| 500-film list, median | 66.99 ms | **51.81 ms** | **22.7% faster** |
| Home screen, median | 79.52 ms | **49.56 ms** | **37.7% faster** |
| First stream byte | 75 ms | **48 ms** | **36% faster** |
| First stream byte through gzip | 78 ms | **60 ms** | **23% faster** |
| 53.79 GiB UHD HDR remux, 60-second window | 12.789 s | **11.262 s** | **11.9% less wall time** |
| 7.21 GiB HEVC MKV remux, 60-second window | 3.314 s | **2.522 s** | **23.9% less wall time** |
| HDR to 1080p H.264 SDR, 15-second window | 11.768 s | 11.749 s | **effectively unchanged** |

That last row is there on purpose. FFmpeg 8.1.2 does not make every transcode
magically faster. On the final reproduction run, tone mapping stayed inside the
noise margin. The real 3.2 win is a more dependable playback path, not one shiny
number rescued from the most flattering run.

Memory did not fall everywhere either. The endurance run starts at 27.3 MiB of
resident memory and peaks at 32.9 MiB. A separate 10,000-film benchmark ends at
44.0 MiB of working set. Startup showed no meaningful improvement, and the
binary is slightly larger. Progress has a bill. At least this one is measured.

## What changes when you press Play

- **Edge no longer chokes on high bitrates.** The player reduces its MediaSource
  buffer target when the browser reaches its byte quota, then retries the exact
  block that was refused instead of dropping it.
- **A risky first playback can recover by itself.** If FFmpeg finishes installing
  during the first HEVC attempt, the player refreshes its state once and moves
  to the compatible path.
- **Pause finally means pause.** After two minutes, Theia releases the stream and
  its FFmpeg process. Resume starts again from the saved position instead of
  burning resources into the void.
- **Films and episodes use one playback service.** Seeking, audio tracks,
  subtitles, quality and progress now share the same clock and lifecycle.
- **Errors say what actually failed.** A full buffer, a dead encoder and an
  unsupported codec no longer hide behind the same vague native browser error.

## Browsers received real engine work

Theia now treats Chromium, stable Microsoft Edge, Firefox and WebKit as separate
targets in the playback suite. Chromium is not counted as proof of Edge, because
that shortcut is how browser-specific failures get promoted to user problems.

The transport supports MediaSource and ManagedMediaSource, adapts to quota
pressure, preserves a six-second startup reserve and falls back to native video
when neither API exists. Codec and frame assertions only run where the engine
actually exposes them. This improves browser coverage without pretending that a
Windows WebKit harness is a physical Safari television.

## Settings stops waiting for the slow answer

The Settings controls no longer wait for the expensive FFmpeg diagnostics path
before becoming usable. Essential settings, server health, library statistics
and update state load together. Hardware and playback diagnostics load
independently and can enrich the page without holding those controls back.

It sounds small. It is not. A configuration screen blocked by five subprocess
probes is a configuration screen that feels broken.

## Hardware is measured, not guessed from a logo

When a transcode is actually needed, Theia probes the hardware encoders compiled
into FFmpeg and keeps only the ones that successfully open on that machine. The
candidate paths cover NVIDIA NVENC for RTX 30, 40 and 50 series systems, Intel
Quick Sync, AMD AMF, Apple VideoToolbox on M-series Macs, Linux VAAPI, Windows
Media Foundation, and CPU encoding through libx264.

Decoder selection goes further. Theia builds a tiny local sample, times software
decoding against the hardware paths available on the current system, and only
keeps hardware acceleration when it wins by a meaningful margin. An integrated
GPU can lose time copying frames back to the CPU, so "hardware" is not treated
as a synonym for "faster" anymore.

The boundary matters: Radeon 890M was physically measured for this release.
NVIDIA, Intel and Apple paths are present, probed at runtime and covered by code
tests, but still need field confirmation on those machines. A compatibility
matrix is not permission to hallucinate benchmarks.

## Theia understands more about the file before choosing a path

Media inspection and playback compatibility are now two separate questions.
Theia records what the file actually contains: container, video codec,
resolution, frame rate, HDR10/PQ or HLG transfer, Dolby Vision metadata, audio
codec and profiles such as TrueHD with Atmos or DTS-HD, channel layout, tracks
and subtitles.

The playback plan then decides what Theia can direct play, remux, transcode or
tone map for the current browser. It never turns "this file contains Atmos" into
"your television can reproduce Atmos". The browser, display, HDMI chain and
receiver still have the final word, and sometimes they reveal almost nothing.

## FFmpeg 8.1.2, with a seat belt

Theia moves from FFmpeg 6.1.1 to **Jellyfin FFmpeg 8.1.2-4** on Windows, Linux
and macOS, for both AMD64 and ARM64. The downloaded archive and the single
executable extracted from it have separate pinned SHA-256 checks. A manual or
altered binary is never silently executed, and FFmpeg is still downloaded only
when playback actually needs it.

This is not version-number collecting. It gives all six targets one build family,
adds a native Windows ARM64 package and brings several generations of fixes to
the demuxers, decoders and filters that touch real media files.

## Logs that help without watching you

Theia now keeps bounded structured playback logs locally. They record plans,
readiness, stalls, buffer depth, automatic quality changes, process failures and
cleanup. Settings can export a support ZIP containing readable diagnostics and
the relevant chronological logs.

Paths, credentials and token-shaped values are sanitized before the archive is
created. Nothing is uploaded automatically. Theia still has no telemetry and no
support cloud quietly staring back at your library.

## Library and updates

- A new stable file enters the library on its first eligible pass instead of
  waiting for an arbitrary extra scan.
- Libraries containing more than 500 series are no longer truncated.
- SQLite list queries avoid loading heavy fields they do not need, and the home
  screen uses two bounded connections for independent reads.
- The updater saves SQLite with its WAL and the configuration, waits for the new
  server to become healthy, and restores the previous executable and data if the
  health check fails.
- Playback processes are bounded, cancellable and terminated during shutdown or
  an update.

## What was actually tested

The local candidate passed the Go test suite, `go vet`, `govulncheck`, npm
audits, 43 JavaScript tests and the Svelte check with no errors or warnings. The
interface guard completed 81 scenarios with three historical skips. Playback
completed 39 scenarios across Chromium, stable Microsoft Edge, Firefox and
WebKit, with five documented skips for APIs unavailable in Playwright's Windows
WebKit build.

A real 7.21 GiB HEVC MKV was played in Edge 152 with decoded frames, a deep seek,
an audio-track change, a long pause and two successful resumes. It ended with
zero playback errors and zero orphaned FFmpeg processes. The endurance gate
opened and cancelled 100 real streams, then completed one continuous 30-minute
stream. All six Windows, Linux and macOS AMD64/ARM64 targets compile without CGO.

The remaining limits are explicit. Safari on physical Apple hardware, television
browsers and GPUs absent from the validation machine still need real field
proof. Theia 3.2 adds no Theia cloud, telemetry, HLS or permanent video cache.

The protocols, campaigns and raw results remain available in the

## Does Theia have to stay in your browser?

This work forced me to ask a larger question: should Theia remain entirely in
your browser?

Browser optimization consumes a disproportionate amount of work. Television
browsers make the problem worse: some are old, vendor-specific, poorly
documented or simply impossible to reproduce without owning the exact screen.
The web still gives Theia its simplest installation story, so I am not announcing
a native application after one difficult week. But the question now deserves a
serious investigation instead of an automatic answer.

The next update will probably dig into that choice and into reducing Theia's
size. First the evidence, then the architecture. There is still a lot to come.
