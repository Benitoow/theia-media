# V3.4 closeout audit and options

Source audit, 29 September 2026, on `codex/v3.4-readiness`. This is a proposal
list, not an expanded release commitment. No native window was opened during
this pass; the maintainer reserved computer use for a later explicit approval.

## Repairs in this pass

| Finding | Change | Evidence and boundary |
|---|---|---|
| The home hero only considered films | Compare film and episode watch timestamps; use the latest interrupted item | Old headless build reproduced the omission; new journey checks episode and film precedence and excludes finished episodes |
| A series had no complete resume choice across seasons | Add profile-scoped `resume_episode` to the series detail, without a schema migration | API tests cover second-season resume, profile isolation, reset and finished episodes |
| Returning to a series kept its old card progress | Reload its detail and displayed season after stopping playback | Headless journey changes 7 minutes to 20 on the series hero, card and home hero |
| Rust dropped the server's `tmdb_name` and watch timestamp | Preserve both fields and resolve artwork on the nested episode | Rust JSON regression test |
| Leaving a building preview could lock later hovers | Cancel the timer, release the request flag and discard stale responses | Headless building-preview leave/re-enter case |
| Native search required accents | Normalise combining marks on query and titles | Headless `shogun` query finds `Shōgun` |
| A film detail survived a profile switch | Clear it with the series selection | Source change; the ordinary profile journey is covered, but this exact open-detail switch needs native confirmation |

`PlaybackHero` now owns the film and episode presentation. The shared progress
helpers live separately from `App.tsx`; a second copy of the hero was avoided.
This is a focused extraction, not a claim that the whole application is clean.

The complete headless render journey passes, as do API/library tests and vet,
44 Rust tests, strict Clippy, formatting, locale/type checks and the production
UI build. The Windows player builds and contains the current hashed UI assets.
The JS chunk-size warning remains. These checks do not establish real-library
native playback or a measured performance gain.

## Remaining checks before freezing 3.4

1. **Native fullscreen:** enter/exit from the caption bar, OSD and keyboard;
   Escape ordering; return rectangle; maximise/restore; another monitor and DPI.
2. **Native episode preferences:** selected audio/subtitles, explicit subtitle
   off, quality changes while paused and playing, accurate clock and resume.
3. **Real series resume:** interrupt an episode, close/reopen the player, resume
   from home and from its series, then switch profiles. Headless proof cannot
   establish the installed libmpv flow.
4. **Bad/offline server address:** responsive window during connect, short
   failure, usable retry and persisted address. The connect probe was moved off
   the UI thread in the previous pass; other remote commands still need work.
5. **Disposable Windows installation/removal:** Apps entry, registered uninstall
   command, shortcuts and removed binaries. The existing installation's key was
   repaired previously, but no real uninstall was run on the maintainer's copy.
6. **Packaged Apple Silicon picture and OSD:** the actual application must draw
   advancing film frames. This is still a release gate, not a Windows result.

## Code risks found, not reproduced as native failures

| Priority | Evidence | Proposed repair and proof |
|---|---|---|
| P1 | `player_preview`, `player_library`, `player_series`, `player_home` and `player_qualities` are synchronous Tauri commands and hold `CLIENT` across HTTP work | Move remote work to a blocking worker with a client snapshot; keep the shared lock short. Inject delayed responses and verify native controls remain responsive |
| P1 | `save_progress()` only logs an HTTP failure; `player_stop()` still succeeds | Retain the unsent position, keyed by server/profile/media, and retry with a visible save state. Disconnect/reconnect without losing or leaking history |
| P1 | `play_episode()` passes no original language; `SeriesMetadata` lacks it | Carry TMDB original language through persistence/API/Rust, including old-cache backfill. Verify VO against a multilingual episode whose default audio is dubbed |
| P2 | Async movie/series detail requests have no navigation generation guard | Discard responses after navigation, server or profile changes. Delay a response, navigate away, confirm it cannot reopen the old selection |
| P2 | `loadLibrary()` and `loadHome()` each couple films and series with `Promise.all` | Preserve the successful half with separate loading/error states. Make one endpoint fail and keep the other catalogue usable |
| P2 | The production JS chunk is 571.47 kB, 179.88 kB gzip, and Vite flags its size | Split settings and detail chunks; measure cold startup and first open. Chunk size alone is not a measured speed problem |
| P2 | `MediaCard` retains a base64 preview per mounted card | Bound the preview cache or use managed blob URLs. Measure heap before/after many hovers and confirm URLs are released |
| P3 | `ContinueEpisodes` calls `GetEpisodeItem` per returned item | Batch the necessary reads if query timing shows a bottleneck; keep next-episode and profile semantics intact |

## Ideas worth considering for 3.4

### Stability first

1. **Cancel a connection attempt.** Allow correcting an address immediately;
   discard the answer to the cancelled attempt.
2. **Reconnect quietly.** A clear offline state and bounded retry, while keeping
   the saved server selected and the settings reachable.
3. **Report whether progress was saved.** A small actionable state when the
   server disappeared, paired with the retry mechanism above.
4. **Protect against late responses.** Reuse the preview generation approach
   for catalogue, detail, connection and profile requests.
5. **Repair Windows registration during maintenance.** Integrate the existing
   repair primitive into an update/reinstall path that detects missing entries.
6. **A small Go/Rust JSON contract corpus.** Check real payload keys, null lists,
   timestamps, TMDB names and optional progress; avoid losing data at the bridge.
7. **A release smoke checklist with one evidence file.** Startup, offline address,
   film, episode, resume, profiles, fullscreen, install/uninstall. Keep each
   platform's proof separate.

### Useful player improvements

8. **VO for series.** Fix the missing metadata contract before polishing the
   language sheet; a label cannot choose a track whose language is unknown.
9. **Watched / reset progress actions per episode.** Build on the existing
   episode progress API; confirm destructive history changes deliberately.
10. **A discreet completed-episode badge.** Finished items currently hide the
    progress rule; distinguish completed from never started without altering art.
11. **Next unwatched episode on the series page.** When nothing is interrupted,
    offer a deliberate starting point. Automatic next-episode playback already
    exists; this would complement it.
12. **One continue card per series.** Keep only the newest interrupted episode
    per show in the short row. This is a product choice, not a current bug.
13. **Remember device volume/mute.** Separate device state from profile language
    preferences; verify startup volume against the engine before implementing.
14. **Remember window geometry safely.** Clamp to the current monitor work area
    after monitor/DPI changes so a disconnected screen cannot hide the window.
15. **A compact keyboard help panel.** Show the existing shortcuts and add a
    clear search shortcut without intercepting text input.
16. **Copy a playback diagnostic.** Version, stream mode, selected tracks and
    engine error; redact private addresses/paths and credentials. Local only.
17. **Explain unavailable quality.** Distinguish no alternative file, no usable
    transcoder and an in-progress conversion, using the actual server answer.

### Cleanup and measured optimisation

18. **Extract the settings sheet from `App.tsx`.** Give preferences, update and
    viewing sections clear ownership; preserve the current interaction contract.
19. **Separate catalogue/navigation and playback state.** Small hooks with clear
    inputs and outputs, without a new state framework for its own sake.
20. **Load settings/details on demand.** Use the bundle split above only after
    comparing startup and first-open costs.
21. **Virtualise very large catalogues.** Measure a realistic large library
    first; preserve keyboard focus, scroll restoration and accessibility.
22. **Bound previews and requests.** A small cache and concurrency limit so a
    fast scroll cannot monopolise networking or memory.
23. **Measure slow SQL before batching it.** Catalogue/continue row latency and
    query count on large libraries, then the same measurements after a change.
24. **Define responsiveness budgets.** Cold start, server failure, detail opening
    and quality switch, with a repeatable fixture and device information.
25. **Document the maintained web boundary.** Keep administration/settings and
    shared API checks clear now that browser playback support has ended.

## Keep for 4.0

Shared cinema rooms, social presence, multi-device coordination, new client
platforms, plugins, AI curation and a redesigned collection system each need
their own product and architecture decision. They are candidates for the next
generation, not reasons to prolong the 3.4 stabilisation indefinitely.

The recommended finish is: settle the remaining P1 risks, run the native checks,
publish only platforms with complete proof, then freeze features and accept
small corrective maintenance. The idea list is a backlog, not a release gate.
